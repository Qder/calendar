# 真机 / 实机通知验收清单

> **本文件描述的验收项，机器人环境均未执行。结论一律为「未验证」。**  
> 请把每项结果（通过 / 失败 + 机型 / 系统版本 + 现象）反馈到群聊或 1:1。

## 验收边界（务必对齐）

| 场景 | 期望 | 不在本阶段承诺 |
| --- | --- | --- |
| Android：前台 / 后台 / **从多任务划掉** | 到点弹出（系统 Local Notifications） | — |
| Windows：点关闭隐藏到托盘，进程仍在 | 到点弹出 | **任务管理器结束进程 / 杀进程后仍弹出** — **不验收** |
| Web（`npm run dev`） | 仅调试页冒烟 | 关标签页后仍弹出 — **不验收** |

## a. 应用前台 / 切到后台 / 从多任务划掉

1. 安装 Debug APK（见 README Capacitor 步骤）。
2. 打开应用 →「申请通知权限」→ 允许。
3. 若弹出「闹钟和提醒」系统页，一并允许（精确闹钟）。
4. 点「30 秒后提醒」，然后分别测：
   - **前台**：停留在应用内，是否到点弹出 / heads-up。
   - **后台**：按 Home 回到桌面，是否到点弹出。
   - **划掉**：从多任务/最近任务把应用滑掉，是否仍到点弹出。

记录：机型、Android 版本、三态各自通过/失败、是否有延迟。

## b. 锁屏状态

1. 调度「2 分钟后提醒」。
2. 立即锁屏（电源键）。
3. 到点后：锁屏上是否显示通知；解锁后通知栏是否仍在。

## c. 重启手机后，待触发是否还在

1. 调度「5 分钟后提醒」（或更长）。
2. 用「列出待触发」确认已登记。
3. **重启手机**（不要先取消）。
4. 开机后：
   - 不打开应用：到点是否仍弹出？（部分 OEM 需自启动，见 d）
   - 打开应用 →「列出待触发」：条目是否还在。

> Capacitor Local Notifications 由系统 AlarmManager 持有；若 OEM 清掉闹钟，重启后可能丢失 —— 请如实记录。

## d. 国产系统需手动打开的开关（逐项）

不同品牌路径名略有差异，请在本机「设置」里搜索应用名 `Calendar` / `日历` 后勾选：

| 品牌/系统 | 建议打开的项 | 本机路径（请填写） | 结果 |
| --- | --- | --- | --- |
| 小米 / HyperOS / MIUI | 自启动、后台运行、省电策略→无限制、通知管理→允许 | | |
| 华为 / 鸿蒙 | 手动管理 / 允许自启动与后台活动、应用启动管理 | | |
| OPPO / ColorOS | 允许自启动、允许关联启动、耗电管理→不限制 | | |
| vivo / OriginOS | 后台高耗电允许、自启动、锁屏清理白名单 | | |
| 三星 One UI | 电池→不受限、休眠应用中移除 | | |
| 其它 | 通知、自启动、电池优化白名单、精确闹钟/闹钟与提醒 | | |

另请确认：

- [ ] 通知权限 = 允许  
- [ ] 「闹钟和提醒」/ 精确闹钟 = 允许（Android 12+）  
- [ ] 通知渠道「闹钟式强提醒」= 高重要性；「仅弹窗通知」= 普通重要性  

## e. Windows：关闭窗口后是否仍按时弹出

1. `npm run tauri:dev` 或安装 `tauri:build` 产物。
2. 「申请通知权限」。
3. 点「30 秒后提醒」或「2 分钟后提醒」。
4. **点窗口关闭按钮**（应隐藏到托盘，进程仍在；托盘可「打开」「退出」）。
5. 到点是否弹出系统通知。

| 操作 | 期望 | 结果 |
| --- | --- | --- |
| 关闭窗口（托盘存活） | 到点弹出 | **未验证** |
| 托盘「退出」/ 任务管理器结束进程 | **不要求**仍弹出 | 不验收 |

睡眠恢复：合盖/睡眠后再唤醒，若已过触发点，唤醒后应尽快补弹（桌面实现会 `rescan`）。**未验证。**

## f. 同步到系统闹钟（N-sys-alarm）— **已取消**

系统闹钟无法选日期，与「当天/前N天」不对齐；入口已下架（插件可留）。**不再验收**本项。

## g. 提醒强度 alarm / banner（N-reminder-kind）— **未验证**

1. `git pull` → 网页有改动时跑 `android:sync`，再 `assembleDebug` 重装。
2. 新建事项：启用提醒 → 「提醒方式」二选一：
   - **闹钟式强提醒**：应走高重要性渠道（声音/震动、尽量 heads-up）。
   - **仅弹窗通知**（默认）：普通重要性渠道，横幅/通知栏即可。
3. 系统设置 → 应用通知 → 应能看到渠道「闹钟式强提醒」与「仅弹窗通知」；分别调一条短延迟提醒对比打断程度。
4. **不**再出现「添加到系统闹钟」按钮。

| 步骤 | 期望 | 结果 |
| --- | --- | --- |
| 选强提醒到点 | 高重要性渠道弹出 | **未验证** |
| 选仅弹窗到点 | 普通渠道弹出 | **未验证** |
| 编辑页无系统闹钟按钮 | 已下架 | **未验证** |

## h. 过期 pending 清理（N-notif-miss）— **未验证**

1. 调试页制造过期残留：或保留历史上「待触发」里已过点的条目。
2. 将 App 划到后台再回前台（或冷启动）→ 再「列出待触发」：过期条目应消失；事项类可收到一条「错过的提醒」即时通知。
3. 未来时刻（现在+3 分钟）的 pending **不得**被清掉。

| 步骤 | 期望 | 结果 |
| --- | --- | --- |
| 回前台清过期 | 过期 pending 消失 | **未验证** |
| 未来 pending | 仍保留 | **未验证** |
